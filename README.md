## Описание

Проект представляет собой сервис для создания, управления и анализа email-рассылок с возможностью администрирования
пользователей и сбора статистики успешных и неуспешных попыток отправки сообщений.

---

## Технологии

- Python 3.12
- Django 5.2
- PostgreSQL
- Bootstrap 5 (UI)
- SMTP сервер (Yandex)
- Redis (для кеширования)

## Установка

1. Клонируйте репозиторий:

```
git clone https://github.com/Rapunzel-Chan/Newsletter_Django
```

2. Создайте виртуальное окружение и активируйте::

```
python -m venv venv
source venv/bin/activate   # Linux/Mac
venv\Scripts\activate      # Windows


```

3. Установите зависимости:

```

pip install -r requirements.txt

```

4. Настройте переменные окружения и параметры базы данных, SMTP в config/settings.py или через .env.


5. Выполните миграции:

```
python manage.py migrate
```

6. Создайте суперпользователя:

```
python manage.py createsuperuser
```

## Запуск

```
python manage.py runserver
```

## Функционал:

Часть 1 — Базовая функциональность
Управление клиентами:
CRUD для получателей рассылок с полями email, ФИО, комментарий.

Управление сообщениями:
CRUD для сообщений с темой и телом письма.

Управление рассылками:
CRUD для рассылок с датами начала/окончания, статусом (Создана, Запущена, Завершена), связанными сообщениями и
клиентами.

Отправка рассылок:
Ручной запуск рассылок из интерфейса и через командную строку.

Логирование попыток отправки:
Каждая попытка отправки письма сохраняется с датой, статусом (Успешно/Не успешно), ответом почтового сервера и связью с
рассылкой.

Главная страница:
Показывает общее количество рассылок, активных рассылок и уникальных получателей.

Часть 2 — Расширенный функционал
Регистрация и аутентификация:
Регистрация с подтверждением email, вход/выход, восстановление пароля.

Статистика и отчеты:
Отображение количества успешных и неуспешных попыток по рассылкам пользователя.

Ограничение доступа:

Пользователи управляют только своими рассылками и клиентами.

Менеджеры могут просматривать все данные, но не редактировать чужие.

Администраторы могут блокировать пользователей и отключать рассылки.

Кеширование:
Серверное и клиентское кеширование для повышения производительности.

## Архитектура и модели

**Client (Получатель):**

* email (уникальный)
* full_name
* comment
* owner

**Message (Сообщение):**

* theme
* content
* owner

**Mailing (Рассылка):**

* first_sending
* last_sending
* status (Создана, Запущена, Завершена)
* message (FK)
* clients (ManyToMany)
* owner

**AttemptMailing (Попытка рассылки):**

* created_at
* status (Успешно/Не успешно)
* response
* mailing (FK)

**User (Пользователь):**

Стандартная модель Django с дополнительными полями и ролями

* email (уникальный)
* phone
* avatar
* country
* token

**Права доступа и роли:**

| Роль          | Возможности                                                                                |
|---------------|--------------------------------------------------------------------------------------------|
| Пользователь  | Управление своими клиентами и рассылками, просмотр статистики                              |
| Менеджер      | Просмотр всех клиентов, рассылок и пользователей, но без права редактирования чужих данных |
| Администратор | Полный контроль: управление пользователями, блокировка, отключение рассылок                |

**Кеширование**

Реализовано с использованием Redis (настраивается в settings.py), кешируются страницы со статистикой и часто
используемые данные для ускорения работы.
